Overview

6년간 새로운 위젯 기능이 지속적으로 추가되면서 편집 경험이 복잡해졌고, 개발 구조에도 레거시가 누적되어 안정성과 확장성에 한계가 생겼습니다.

팀은 장기적인 유지보수와 기능 확장을 위해 V2 전면 개편을 추진했습니다. 기존 사용자 콘텐츠의 호환성을 고려하면서 편집 UX/UI를 재설계하고, 개발팀과 새로운 편집 구조를 정의했습니다.

Service
Photowidget
Role
UX/UI 구조 재설계 · 편집 모델 정의 · 개발 협업

01 — Background

6년간 기능은 계속 추가됐지만, 편집 구조는 개편되지 않아 UX/UI가 복잡해졌습니다.

[V1 — 누적된 편집 UI]
[V2 — 개편 목표 구조]

Why rebuild

서비스 운영 과정에서 새로운 위젯 기능이 지속적으로 추가됐지만 기존 편집 구조는 그대로 유지됐습니다. 위젯 종류마다 편집 방식이 달라졌고, 변경된 iOS 정책에 맞지 않는 기능도 남아 있었습니다. 레거시 버그가 반복되고 신규 위젯 확장도 어려워졌습니다.

장기적인 유지보수와 기능 확장을 위해, 데이터 이전 위험을 감수하더라도 V2를 새롭게 구축하기로 결정했습니다.

기존 구조의 문제

  • 복잡해진 UX/UI
  • OS 기능과 맞지 않는 편집 화면
  • 레거시 버그와 확장 제약

V2 개편 목표

  • 편집 UX/UI 구조 개선
  • 제품 안정성 개선
  • 신규 위젯 확장 기반 마련

02 — Problem definition

위젯 편집 흐름을 하나로 정리하고, OS에서 지원하는 기능에 맞게 편집 경험을 재설계해야 했습니다.

세부 사용자 행동을 확인할 이벤트 데이터가 부족해 신규 입사자 온보딩 분석 자료와 직접 사용하며 발견한 문제를 기반으로 개선 과제를 구체화했습니다.

스타일을 바꾸려면 편집을 다시 시작해야 했습니다.

편집 화면을 유지하면서 여러 위젯 스타일을 탐색하고 변경할 수 있는 흐름이 필요했습니다.

Problem 02

OS 기능과 실제 편집 UI가 일치하지 않았습니다.

홈 화면과 잠금 화면은 지원 기능이 다르지만 하나의 편집 화면에서 토글로 전환했습니다. 잠금 화면에 적용되지 않는 기능까지 노출되어 편집 결과와 설치 후 모습이 달라졌습니다.

After · OS 환경에 맞는 독립 편집뷰와 프리뷰

개발팀과 구현 구조를 논의한 결과 두 환경에 각각 독립된 편집 구조를 제공하기로 했습니다. 홈/잠금 화면의 진입점과 편집뷰를 분리하고, 잠금 화면은 iOS에서 실제 적용 가능한 기능을 기준으로 UI와 프리뷰를 다시 구성했습니다.

04 — Design 02

편집 화면에서 위젯 스타일을 바로 변경할 수 있도록 제작 흐름을 개선했습니다.

[V2 — 스타일 변경 인터랙션]

편집 전에 선택해야 했던 위젯 스타일을 Custom > 위젯 스타일 영역으로 이동했습니다. 사용자는 편집 화면을 나가지 않고 여러 스타일을 변경하고 비교하며 제작할 수 있습니다.

Before

스타일 선택 → 개별 편집뷰 → 나가기 → 다른 스타일 선택

After

편집뷰 유지 → Custom에서 스타일 선택 및 즉시 변경

UI × implementation model

새로운 편집 방식을 위해 레이어 기반 구조를 정의했습니다.

공통 바탕인 Background와 그 위에서 변경되는 위젯 요소인 Custom으로 UI를 구분했습니다. 개발팀과 기존 구현 방식의 제약을 논의하고 이 구분을 코드에서도 레이어로 적용하기로 합의했습니다.

V2에서는 동일 스타일이 모든 크기에 일관되게 적용되도록 규칙을 정리했습니다. 하지만 이를 그대로 적용하면 기존 중형 위젯에 결합된 두 번째 디자인이 사라졌습니다. 30개 이상의 기존 디자인 중 절반 이상이 이런 복합 구성이었습니다.

Compatibility

기존 복합 디자인은 마이그레이션 과정에서 Dual Mode로 반영해 원래 모습을 유지했습니다. 사용자는 두 모드를 전환하고 오른쪽 디자인도 직접 선택할 수 있습니다.

기존 디자인 호환성을 지키면서 서로 다른 위젯을 조합하는 편집 자유도도 확보했습니다.

Technical constraint

S·M·L을 독립 제작하는 방안도 검토했지만, 기존 콘텐츠를 세 개로 분리하면 데이터와 앱 용량이 증가할 수 있어 기존 통합 구조를 유지했습니다.
