위젯 편집 화면 개편

포토위젯은 6년간 서비스를 운영하며 다양한 위젯 기능을 추가해 왔어요. 이 과정에서 복잡해진 위젯 편집 화면을 V2로 전면 개편해 기존 레거시를 정리하고, 새로운 구조에 맞춰 편집 UX를 재설계했어요. 저는 프로젝트에서 기존 기능과 UX 문제 분석, UX/UI 재설계, 마이그레이션 UX 설계 및 개발 협업을 주도했어요.

Background

위젯 편집 기능은 수년간 쌓인 레거시로 인해, 더 나은 사용자 경험을 제공하기 어려웠다

포토위젯에서 위젯 편집은 사용자가 직접 위젯을 만들 수 있는 핵심 기능이에요.

그런데 수년간 서비스를 운영하며 새로운 위젯 기능이 추가됐지만, 편집 구조는 그에 맞춰 개선되지 않아, 레거시가 쌓이면서 더 이상의 기능 확장이 어려워졌어요. 이에 팀에서는 단순한 기능 개선만으로는 이를 극복하기 어렵다는 공감대가 형성됐어요. 따라서 V2로 재구축하는 편이 장기적인 유지보수와 기능 확장에 유리하다 판단해 개편을 결정했어요.

Problem Definition 이미지 플레이스홀더

Process

정성적 데이터와 POC를 기반으로 설계하기

시작에 앞서 개편 전략이 필요했어요. 왜냐하면 참고할 정량적 데이터가 부족했고, 방대한 양의 마이그레이션을 해야하기 때문에 V1과의 호환성을 최우선으로 해야했어요. 그래서 이러한 병목을 고려해 아래와 같은 방식으로 프로젝트를 진행하고자 했어요.

1. 신규 입사 시 작성하는 ‘기능 문제점 분석 자료’와 CS를 참고해 인사이트를 도출하고

2. 이후 설계한 화면을 POC 하며 V1과의 호환성을 확인하고 개선해요.

Problem 이미지 플레이스홀더

Problem 01

위젯 디자인 변경 시 불필요한 화면 이동이 많다

V1에는 위젯 디자인 선택과 세부 편집 화면이 분리되어 있었어요. 이로 인해 사용자가 편집 중 디자인을 변경하려면 편집 화면에서 나간 후 → 재선택하고 → 다시 편집 화면으로 진입해 번거롭다는 의견이 많았어요.

Problem 이미지 플레이스홀더

Problem 02

편집 화면에서 본 위젯과 실제 설치된 모습이 달랐다

홈 화면과 잠금 화면은 각각 OS 기능 정책이 달라요. 하지만 V1에선 지원 속성이 다른 두 위젯이 하나의 편집 구조에 묶여 있어, 작동하지 않는 기능들이 혼재됐어요. 이로 인해 편집 프리뷰와 실제 설치 결과가 달라, 이와 관련한 CS 문의가 많았어요.

Solution 이미지 플레이스홀더

Solution

홈·잠금 위젯 편집 화면 분리

홈 위젯과 잠금 위젯은 각 OS 기능 정책이 다르기 때문에 이를 각각 적용할 수 있도록 두 개의 편집 화면으로 나누고자 했어요.

그런데 한 화면에서 편집하던 기존 사용자 경험과 달라, 배포 초기에 혼란을 줄 수 있었어요.

이에 PO님과 논의하며, 화면을 분리하는 것이 향후 정책 변화와 확장성 측면에서 기대 효과가 클거라 봤고, 따라서 편집 화면을 분리하기로 결정했어요. 이후 지원하는 OS 정책을 재검토해 각 화면 기능에 반영했어요. 그 결과 V1에서 발생했던 앱 내 프리뷰와 설치 시 위젯 모습의 불일치를 해결할 수 있었어요.

Solution 이미지 플레이스홀더

Solution

편집 페이지 내에서 위젯 디자인을 변경하도록 개선

개선한 위젯 편집 화면은 다양한 종류의 위젯을 한눈에 볼 수 있게 해 이를 자유롭게 변경하며 쓸 수 있도록 설계했어요.

사용자는 위젯의 타입을 정하고 그 타입의 하위 디자인을 선택해야 해요. 이를 직관적으로 보여주고자 위젯 타입과 하위 디자인을 썸네일 위계로 구분했어요. 또한, 위젯의 타입에 따라 커스텀 기능들이 다르기 때문에 공통 기능은 상단에, 그 아래에는 타입에 맞는 커스텀 기능을 배치해 타입 전환 시 일관된 경험을 주고자 했어요.

Solution 이미지 플레이스홀더

Solution

레이어 개념을 도입한 위젯 모듈 구조

앞서 개선한 화면을 POC 하는 과정에서 ‘위젯 디자인 변경 시 이미 설정한 배경까지 함께 바뀌는 문제’가 있었어요.

이는 편집 구조는 V2인데, 위젯 모듈은 V1 구조를 그대로 쓰고 있어 생긴 호환성 이슈였어요.

Challenge: 따라서 V2 구조에 맞는 위젯 모듈 방식을 설계해야 했고, 이를 위해 레이어 개념을 도입했어요.

레이어1은 [배경], 레이어2는 [위젯 커스텀]으로 나누어 독립적으로 편집할 수 있도록 했고, 이를 [배경-커스텀] 투탭으로 구분했어요. 이후 신규 위젯도 같은 구조로 확장할 수 있도록, 개발팀과 논의해 개발 구조에도 레이어 개념을 동일하게 적용했어요.

v

Migration

V1 호환성과 위젯 편집 자유도를 함께 확보한 [싱글/듀얼 모드]

위젯은 S, M, L 사이즈로 제공해요. 그런데 M 사이즈는 가로가 긴 형태라, V1에선 좌우에 서로 다른 두 디자인을 묶은 전용 디자인으로 제공되었어요. 이는 사이즈마다 구성이 달라 편집 기능을 일괄 적용하기 어려워, V2에서는 사이즈와 관계없이 하나의 위젯 디자인이 동일하게 적용되도록 변경했어요.

다만 마이그레이션 시, 기존 M 사이즈 위젯이 이전과 다르게 보이는 호환성 문제가 있었어요. 이에 M 사이즈의 좌우 분할 구조를 활용해 싱글/듀얼 모드를 추가했어요. 듀얼 모드에서는 왼쪽에 기본 디자인을 유지하고 오른쪽은 개별 선택할 수 있도록 해, 기존 위젯은 이전 모습 그대로 옮기면서 커스텀 자유도도 함께 높였어요.

Outcome

Lesson learns

  • 위젯 작동 관련 CS 월 약 30건 → 10건 미만

    V2 출시 이후 위젯 작동과 관련된 월간 CS가 약 30건에서 10건 미만으로 감소했습니다.

  • 출시 후 사용성 설문 약 60% 긍정 응답

    개편 이후 진행한 사용성 설문에서 약 60%의 긍정 응답을 확인했습니다.

  • V2 편집 구조 기반 신규 위젯 3종 출시

    개편한 편집 구조를 기반으로 신규 위젯 3종이 출시되었습니다. 이를 통해 V2 구조가 후속 기능 확장에 실제로 쓰일 수 있음을 확인했습니다.
